## Q1 — Problem and target mapping

Smartphone GUI agents repeatedly inspect screens and issue next actions. Requests preserve instructions but rewrite recent history, so chat-oriented prefix checkpointing misses reusable context. Hybrid linear-attention models maintain recurrent state; speculative decoding additionally needs short rollback states. A loaded NPU model may also keep accelerator power votes active between bursts.

## Q2 — New-regime relevance

Native to repeated GUI-agent steps and stateful mobile interaction. The mechanism is software/runtime/backend optimization for a new request pattern, not new CPU microarchitecture.

## Q3 — Falsifiable hypothesis

Saving recurrent state at the actual divergence point between successive prompts, keeping most prefill on NPU matrix hardware, generating only a short rollback tail, fusing verification kernels, and releasing active NPU power votes between bursts can reduce per-step latency/energy and idle power. It fails if prompt prefixes are not reusable, model architecture differs, state storage overhead dominates, or power-vote transitions cost too much.

## Q4 — Mechanism and alternatives

- Cross-request recurrent-state checkpoint at prompt divergence, rather than generic chat-turn boundaries.
- Short per-token tail for speculative rollback states to preserve NPU matrix-unit use.
- Verification kernel reads each weight block once for proposed tokens.
- Fused operators reduce intermediate memory traffic.
- Between bursts, retain model weights but release active NPU session power requests; restore active execution on next task without model reload.

Baseline is llama.cpp's fastest NPU configuration, not an arbitrary CPU-only baseline. Related repository baselines include llm.npu/ShadowNPU, Agent.xpu/HeRo, and existing NPU runtime/session management. These are not all directly comparable because model, device, workload and backend differ.

## Q5 — Experimental setup

Fine-tuned 4-bit Qwen3.5-4B policy on Snapdragon 8 Elite. App set includes 21 Chinese apps with known correct actions and text/screenshot requests; replay trace appends 40 steps from five recorded episodes. Evaluation uses real phone interactions/traces; some profiling uses fan cooling. Paper also tests a next Snapdragon generation for text-step latency. This is a bounded GUI-agent dataset, not broad production traffic.

## Q6 — Results

On Snapdragon 8 Elite, relative to llama.cpp's fastest NPU configuration:
- Text-based screen-description step latency: -30%.
- Screenshot step latency: -16%.
- Energy per text step: -33%.
- Loaded-model standby power: 0.76 W → 0.22 W.

Next Snapdragon generation text-step latency reduction reported as 27%. Preserve the exact denominator and workload. Do not call these whole-task completion speedups or all-day battery savings.

## Q8 — Fact / inference / not established

- **[FACT]** The paper implements Tandem in llama.cpp and a Hexagon backend and evaluates GUI-agent traces on Snapdragon devices.
- **[FACT]** It reports the specific latency/energy/standby-power results above against llama.cpp's fastest NPU configuration.
- **[INFERENCE]** Runtime state reuse, backend-aware speculative rollback and NPU power-vote control deserve stronger treatment in CG-06/C.
- **[INFERENCE]** B-residual should distinguish ordinary recurrent-state checkpointing and NPU session power management (software-visible) from any still-unproven cross-engine physical validity residual.
- **[INFERENCE]** This is counterpressure against broad claims that semantic progress or Agent state requires hidden CPU hardware: important gains can come from prompt divergence and explicit runtime state.
- **[NOT ESTABLISHED]** A/B-residual is disproven; all Agent state is reconstructible; or new CPU/ISA features are required.
