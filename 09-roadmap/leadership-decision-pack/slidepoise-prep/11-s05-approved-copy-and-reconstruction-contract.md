## 二、必须精确重建的边

机器可读的 [S05-edge-contract-v02.json](generated-images/formal-content-v02/S05-edge-contract-v02.json) 是 node_id、from、to、edge_role 的正式依据，包含 **N1—N9（其中 N4a/N4b 两分支，共 10 个逻辑节点）与 E01—E13（13 条逻辑边）**。这些统计仅供技术制图人员审图，不建议放到投影标题区。

关键必读链路：

```text
[用户目标] --> [任务规划] ----(可选)----> [查询重写] --> [检索 A]
                   |                                 \-> [检索 B（可并行）]
                   |----(不重写时)------------------------> [检索 A]
[检索 A / B 的必需结果] --> [聚合/重排] --> [推理/生成]
                                                     |----(需工具且授权)--> [工具操作] --|
                                                     |----(不需要工具)------------------|--> [实际效果验证]
                                                                                               |
                                                                                      [状态更新/结束]
                                                                                               |
                                                                                       (如继续) -> [任务规划]
```

源/目标/条件边不能由 PowerPoint Designer、OCR 或 image2.5 重新猜。为尽量避免拥挤，优先采用分层 lane：主路径横向→必要步骤，下侧两条条件分支，反馈线外绕且标注「如需继续」。如果准确性与复杂美化冲突，优先准确性。

## 六、S05 讲者备注必须覆盖的六项

1. 动态 Agentic RAG/Agent 计划导致部分未来 DAG 节点与依赖只有运行时才能看到，传统固定执行图不足以应对变化。
2. HeRo 的贡献是对部分可见 Stage DAG、阶段关键度/异构亲和性/资源动态放置；本图是结构解释，**不是 HeRo 原图**。
3. 资源不是按“哪个 Agent 属于哪个计算单元”静态划分，而是按任务阶段、算子/模型、NPU 启动/同步/回退与 DRAM 代价选择；GPU/NPU 并不对所有场景占优。
4. 结果验证与状态更新是 Agent 任务控制路径；某个工具 API 返回成功不等于已确认外部效果。
5. SERENO 则证明共享 DRAM 带宽争用影响前台体验，后台 Agent 的调度应考虑 QoE；不要将 SERENO 误当多 Agent CPU/NPU 算子性能评估。
6. 强系统软件已能控制调度/资源/状态；本页不证明需要新增 Agent 专用 CPU 微架构，也不展示无证据的延迟/能耗改进数据。
