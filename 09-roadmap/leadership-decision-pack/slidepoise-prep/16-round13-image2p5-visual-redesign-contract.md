## 1. 视觉审核失败的确切原因

| 维度 | Round12 缺陷 | 重设计验收 |
|---|---|---|
| 主体构图 | 四页均为大标题 + 左右浅蓝框 + 箭头 + 底部引用 | 每一页须有**对应技术概念的独特主图**；第一眼能区分它们是在讲算子分解、内存资源争用、可信结果核验还是信息可观察性 |

## 2. 四页独立的视觉创意（禁止一键套卡片模板）

### S07｜两套 NPU 软件机制的「异构计算分工剖面」

**画面目的**：让技术领导不读大段文字就看出 llm.npu 与 ShadowNPU 是两条机制路线，优化对象与 CPU/GPU 参与方式不同。

- 视觉左半：动态 Prompt 长度 → 多个复用静态子图块；中央用小尺寸的 NPU INT8 计算区纹理，旁侧有**独立的 CPU/GPU 稀疏 outlier 通道**，最终汇合，不得画成全部运算迁到 NPU。
- 视觉右半：Attention token 热度**示意矩阵**（没有伪造标尺和百分比）→ NPU 低精重要位置估计 → CPU/GPU 高精 top-k 与稀疏残差；标明主要 Prefill Attention、**Decode 完整 Attention 未下沉**。
- 两侧图形语言需要同一配色，但**不同的机制几何**：左侧图块重用/双路汇合；右侧稀疏矩阵/局部高精聚焦。底部只有一句差异化结论，不再摆泛化流水线。
- 图内算法/硬件标签按 [S07 内容合同](content-lock-round11/S07-approved-projection-copy-2026-10-26.md)。论文基线/设备不要凭模型自动补出。

### S09｜「动态 DAG 调度 vs 共享 DRAM 前台 QoE」双问题系统图

**画面目的**：明眼可见两个不同的系统瓶颈与 Runtime/OS 的协作接口。

- 左侧主视觉：多分支 Agentic RAG Stage DAG，覆盖 CPU/GPU/NPU 三条**平行资源执行泳道**，资源放置箭头明确连接到阶段，不是上下堆卡片；强调关键路径和后续阶段局部可见。
- 右侧主视觉：前台 App 交互帧链（概念时间刻度，不带未经证实的 ms）与后台 LLM 对同一 DRAM/带宽通道的竞争，突出可分配资源控制/前台延迟保护；不使用真实 SoC die/floorplan。
- 底部居中放小型 Runtime/OS 控制汇聚中心，两侧输入是“动态阶段调度”和“共享带宽/QoE协调”，不是 HeRo 数据直接导致 SERENO 数据的因果链。
- 只显示来源和定性结论。**禁止**将 HeRo 两个消融数值作统一平均、把 SERENO 前台卡顿改善说成算子加速。

### S10｜「操作授权—外部世界核验」安全结果闭环

**画面目的**：用户一眼看清**API 发送成功**与**真实目标完成**是两次独立判定。

- 视觉主图：左侧“用户意图/授权/目标新鲜绑定”作为权限门；中间工具/API 调用区像**受控沙箱**；右侧“外部系统状态”独立实体（非手机 CPU 硬件模块），用回读箭头**反向返回**效果验证中心。
- 在效果验证处分成功（完成确认）与失败/目标过期（补偿、取消、有限重试）两条清晰分叉。失败边应有触发条件与明确终止/重试边界。
- 用不同线型/空间表达请求路径与回执路径，不能所有箭头都从左到右；流程结构要体现回读和校验关系，而非五个等宽框相连。
- OutcomeReceipt 只称“本研究建议的效果回执接口”；不应被美术图画成 Apple/Android 已发布统一标准。

### S11｜软件可观察证据 vs 未证实私有状态的「证据边界地图」

**画面目的**：一眼可见绝大部分语义进度信息已有软件基线，真正待证明的是强基线之外**是否存在**未被观察到的增量信息。

- 核心主视觉占大多数面积：应用/Agent / Runtime 观察层（目标、历史、DAG、中间产物、验证、权限/资源）进入可观察的 **Ledger + 语义摘要中心**，输出调度/路由/结束/恢复的不同控制接口。
- LAS、ProgRouter、ProAgentBench 不是三条假数据柱，宜作为主图边缘三个“证据节点”，分别指向验证门控、进度路由、历史情境。
- 外围留一块**小而清楚的虚线未知区**：完整软件历史之外是否有不可复建 RequiredProgress？使用问号、证据门槛和“未证实/条件研究”标签，绝不画成实体 CPU 寄存器或确定新指令。
- 强基线视觉面积显著大于未知假设，表达研究结论权重；保留公开软件/云端研究不等于手机 SoC 实测的边界。

## 3. 统一的 Image2.5 → 技术复核 → 受控目标 PNG 工作流

1. **每页单独**让 Image2.5 进行构图探索，不再以一个“四页/八页蒙太奇”代替单页设计。让画面占用技术意义所需的面积与留白，而不是把四页套入通用卡片。
2. 用冻结的 2048×1070 substantive 画布为导向，制作具体布局；完整 16:9 预览仅按既定全页 2048×1152、header/footer 各41px 组合。
3. 技术词、论文号/年份、数据和主要箭头精确对照 `content-lock-round11`。对于模型生成的文字错拼、自动加的数字/图线、示意实体误标，必须更换受控层；不允许保留伪数据的条形高度或错误因果方向。
4. **G2-ART 视觉 QA**：单页主视觉是否独特、有科研示意可信度、蓝白协调、有合适字号、信息权重与留白，是否能冷读图形关系；比例/边界/技术事实之外也要检查。
5. **G2-FACT 科学 QA**：每个来源“支持什么/不支持什么”、工作负载/CPU↔NPU分工、所有条件性边、是否擅加数值；再审中文/对齐/箭头端点。
6. 用户确认视觉后，才将相应 PNG 改名/提升为 SlidePoise 可使用的合格目标，并将实物/哈希/Notes 归档到 Library 和 GitHub；未上传到 GitHub 的二进制，不得虚报已提交。
7. 已获用户视觉批准的 S02、S03、S05、S06、S08、S15 **保持不动**；Round12 S07/S09/S10/S11 全部从 G2 重新走审批。
