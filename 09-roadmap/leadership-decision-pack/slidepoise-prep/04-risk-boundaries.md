## 3. 页面级图形语义风险矩阵

| Slide | 高风险视觉对象 | 精确关系合同 | 不允许的视觉错误 |
|---|---|---|---|
| S03 | 三层决策结构 | 「工程优先」/「条件储备」/「证据不足的新硬件」是不同决策状态 | 储备用与工程相同的已批准勾选；把 0 写成 0 个 CPU 机会 |
| S04 | 动态 Agent 生命周期 | 执行后核验→状态修订或恢复，低功耗是否触发是前置/旁路决策 | 无条件固定环路；每步都触发全部 CPU/NPU |
| S05 | 动态 DAG | 有向依赖、部分并行、条件分支；用明确 source/destination/edge_role | 弯折连线悬空、跨越节点误连、没有箭头的同色线 |
| S06 | 两类阶段、开销分解 | Prefill/Decode 不等价，单算子优势≠完整任务优势 | 用高度相反的柱表达错方向，启动/同步开销假定互不重叠 |
| S07 | 两篇 NPU 软件机制 | 优化 NPU 主计算 + CPU/GPU 必要残差，精度/形状相关 | 两篇加速相乘；画成完全无 CPU 控制 |
| S08 | SoC 与 CPU/SME | CPU 核包含标量/SIMD/SME2 资源，NPU/GPU 是不同引擎 | SME2 在 CPU 框之外，误画成专用硬件芯片 |
| S09 | DAG 与 DRAM/QoE | HeRo 任务放置，SERENO 共享带宽/前台保护 | 研究一的延迟变化指向研究二的能耗数据作为因果 |
| S10 | 权限→动作→回执→验真 | 真实外部结果验证是工具成功之后的独立判定；失败有边界恢复 | API 200 响应直接连接「目标已完成」 |
| S11 | 可观察/私有状态 | 已知可观察 ledger 内状态 ≠ 假设中的不可观察私有状态 | 用硬件寄存器图示假定已存在 Agent RequiredProgress 物理寄存器 |
| S12 | F/P/V 跨层能力 | 功能主题横跨 Agent/Runtime/OS/CPU/内存层 | 三条主题画成三颗新的 CPU SoC 模块 |
| S13 | 三条工程能力链 | LLVM/内核库、Agent 平台、Runtime/OS 三种 owner 协作 | 全部从 CPU 微架构一个框独立输出 |
| S14 | 三研究门槛 | 每个储备的强基线、残余问题、升级证据依次成立 | 用完成度/成熟度百分条制造未经证实的结论 |
| S15 | 年度×技术层路线 | 年份表示规划建议，2029 新硬件选项需条件/外部证据 | 使用「量产」「已完成」「确定流片」箭头 |
| S16 | 来源可信度 | 直接事实↔推断↔假设↔证据尚不足是论证层级，不是线性科学证实度 | 「尚无足够证据」写作「物理上不存在」 |
| S17 | 决策收束 | 现在可做的建设方向与何种证据可重开严格分开 | 结尾提一个没有条件的 Agent 专用 ISA 研发立项 |

## 4. 原始证据与第一方平台陈述必须隔离

### 4.1 比较对象
- **手机实测**：PAPER-009 / 057 / 059 / 098 / 003、TOOL-012（第一方厂商/生态报告，独立性较弱）；逐项看测量对象与基线。
- **不同设备 CPU 研究**：PAPER-052 部分测试是 Apple M4 Pro，不是智能手机。MediaTek Dimensity 9500 测试若未逐表确认，不允许拿苹果平台的能耗值替代。
- **云端/软件研究**：PAPER-119 LAS、PAPER-121 ProgRouter、PAPER-044 ProAgentBench 可说明动态软件控制强基线，但不能替代手机算力、热、QoE 证据。
- **平台 API**：VENDOR-027 Android NPU Manager（Android 17+ 平台文档，不保证所有设备已落地）；VENDOR-029 Qualcomm QNN shared buffers（部分索引章节，访问限制）；VENDOR-032 Apple Foundation Models 会话/工具功能（第一方披露，不是硬件验证）。
- **专利**：PATENT-024（CPU 异构簇与缓存先例）、PATENT-032（需求/语义缓存有效性申请）、PATENT-033（软件事务恢复申请），各权利要求边界不同；不等于产品已量产、也不等于 FTO 意见。
