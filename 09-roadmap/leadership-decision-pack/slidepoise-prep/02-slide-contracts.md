**备注主线**：先按层逐项解释技术内容，再分别指出这些是工程/平台建议、未验证储备与无证据的硬件主张；解释旧 A 方向已正式降级，历史评分不可复用。

## S04｜04/17 — 持续任务、可信动作和可修订状态正在改变手机执行负载

**主视觉**：环状或部分循环的用户任务生命周期：意图→规划→推理/检索→工具执行→外部效果核验→状态更新/必要时重试；「低功耗准入」作为进入条件，不要无条件插入每一条执行路径。使用自然语言标注反馈环。

**证据**：Apple Foundation Models 会话/Tools 官方 API（VENDOR-032）、PAPER-044 的历史情境、PAPER-098 的动态 Agentic RAG；产品机制与研究观察分层。

**备注主线**：逐项解释四类变化如何改变 CPU 控制、Runtime 决策、存储有效性与低功耗；说明并非所有手机任务具备全部环节。

## S06｜06/17 — CPU 与 NPU 的优劣取决于阶段、算子形状和执行交接成本

**页面任务**：用真实手机实验说明为什么不能用峰值 TOPS 判断端到端收益。

**投影必含**：Prefill 与 Decode 的负载差异；阶段总成本不仅包括计算，还包括启动、同步、布局/复制、CPU fallback、排队/争用。选用 PAPER-009 同一条件下的有来源数字，推荐展示「该测试栈 NPU Prefill 相对 6 核 CPU 慢约 1.27–1.62×；Decode 的 MUL_MAT 单算子 NPU 延迟约低 1.55–1.67×；通信成本约占 NPU 路径 9.9–13.0%」；若放具体数值必须带测试条件、单位/分母及原图/表来源。

**主视觉**：上半部「Prefill vs Decode」两阶段与不同优势；下半部「计算时间 + 非计算成本」概念分解。概念式不是论文原始统一实测方程；若数字过密，精选两项而把完整数据放到备注。

**证据**：PAPER-009 / arXiv:2605.27435；Snapdragon 8 Gen 3、Hexagon v75 特定 CPU/NPU 软件栈。必须区分单算子加速与完整 Decode/整次任务加速。

**备注主线**：完整交代设备、模型/软件栈/比较对象、不同阶段与 Amdahl 类型端到端限制，再解释不能外推下一代 NPU 或所有手机。

**拒收**：将「NPU 的单一矩阵算子快」写成「完整 Decode 快相同倍率」；使用没有原始分母的图柱；把 1.27× 写成 CPU 对所有 Prefill 永远更快。

## S08｜08/17 — 现有 SME2 与编译布局协同已提供有证据的 CPU 优化空间

**页面任务**：解释 CPU 不需新的 Agent ISA 也有可落实的优化机会。

**投影必含**：CPU 核内部的标量/向量与 SME/SME2 矩阵能力，受算子形状、精度、tile 分区、pipeline、packing、ZA/PSTATE.SM 与 ABI 边界影响；单独一个数据面板展示 vivo X300 上 ExecuTorch/KleidiAI SqueezeSAM 特定单核 CPU 路径 INT8 555.8→304.1 ms、FP16 1163.0→298.2 ms（两项均为该官方报告），并说明 SME2 路径数据搬运约 40%。第二证据 SMEPilot 可以示机制和最高 3.94×，但与 vivo X300 不得混成同一平台实验。

**主视觉**：CPU 核外框内嵌「常规执行 / SIMD / SME2 矩阵」逻辑能力；右侧分别排列 SMEPilot 机制示意与 vivo X300 量化结果，明确标出平台。不可把 SME2 放到 CPU 外框外与 NPU 并列。

**证据**：PAPER-052（SMEPilot：多平台，Apple M4 Pro 能耗数值**不是手机能耗**）；TOOL-012（PyTorch/ExecuTorch 官方文章，vivo X300）；LLVM AArch64 SME、MLIR ArmSME/Linalg 官方文档。

**备注主线**：解释 CPU 内部 SME 指令工作机理、SME 和 ABI 正确性、布局复用与内存数据移动，逐项解释两篇/类来源的设备、数据意义与限制。

**拒收**：SME 与 CPU、NPU 三个并列处理器；把 M4 Pro 焦耳值写成手机电池结果；把视觉分割测试冒充 Agent 端到端测试。

**备注主线**：解释每层负责什么，以及边界跨越时依靠接口与协议；当前跨层工程成熟度不能自动推出新硬件必要性。

**拒收**：三个主题变成三颗平级芯片模块；箭头找不到来源/终点；主题名字只写 F/P/V 要观众猜。

## S13｜13/17 — CPU 编译、可信工具和异构系统是三条不同责任域的优先工程路线

**页面任务**：具体告诉技术负责人有哪些可控的工程切入点，以及需要哪些协作。

**投影必含**：路径 A「现有 ISA + LLVM/MLIR + 微内核/packing + CPU/NPU 分阶段放置」——编译/CPU 库负责 C1–C3，放置 C4 需要 Runtime 协作；路径 B「权限/目标确认 + 结果回执 + 验证/有界恢复」——Agent 平台/OS；路径 C「动态 DAG + NPU 管理 + DRAM/QoE」——Runtime/OS。每条用「输入 → 控制点 → 期待改善的可观察指标」呈现，不能虚构已量化收益。

**主视觉**：三条不同所有权的工程能力链，并用跨链接口说明「编译↔Runtime」「Agent↔OS」。不要让三个方向视觉上都指向「CPU 硅片新增模块」。

**证据**：current.md、DEC-PORTFOLIO-002、PAPER-009/052/098/003、TOOL-012、平台官方文档；研究编号只存备注。

**备注主线**：按技术团队解释五个控制点、强 NPU 基线与跨团队接口，再说明哪些属于可立项工程方向、哪些未获得预算批准。

**拒收**：把技术 owner 画成真实已指定人员；将优先工程包装为硬件差异化投资；在投影上只列 CG-06/PT-A/C 而无解释。

## S14｜14/17 — 三项研究储备必须先证明强软件基线之外仍有独立价值

**页面任务**：避免为填满硬件创新数量而把未知问题当结论。

**投影必含**：三项窄假设：
1. 「任务进度信息」：完整软件账本外是否还有增量信息？
2. 「跨处理器派生状态」：软件版本、缓存失效、OS 队列机制后是否还有物理状态成本？
3. 「CPU 续执行局部性」：普通亲和性、迁移/共享缓存机制之外是否还有不可吸收的损失？
每项有「现有强基线→缺口→升级条件」，另以较低权重列「低功耗平台/共享缓存跟进；语义新 ISA 暂不立项」。

**主视觉**：三行证据门槛矩阵，最后一列统一展示「需新增公开原始证据」；不使用进度条或勾选表示三项已通过。

**证据**：DEC-A-008、DEC-PORTFOLIO-002，LAS/ProgRouter、QNN shared buffers、Android NPU Manager、缓存迁移专利和公开 CPU 机制。

**备注主线**：逐项解释对照的现有机制与能够「重新评估」的公开测量/因果证据；保留各储备 open 状态。

**拒收**：对未证实方向给未经审定的预期百分比收益、技术成熟度分数、已批准设计里程碑。

## S15｜15/17 — 未来三年宜先夯实现有 ISA 与软件基础，再条件性研究硬件残差

**页面任务**：形成面向管理的时间分层建议，绝非厂商量产或团队已承诺的排期。

**投影必含**：纵轴建议合并为五层「CPU/编译」「异构 Runtime/OS」「Agent 可信动作」「内存/状态」「主动低功耗」；横轴 2027、2028、2029。
- **2027**：现有 ISA lowering/内核与布局；阶段 DAG/DRAM/QoE 基础；权限/结果验证；软件状态有效性；低功耗既有平台跟进。
- **2028**：CPU/NPU capability-aware 放置与 ABI/接口；模型优先级/取消/恢复；跨 App 安全合同；跨引擎状态版本兼容；隐私和能耗准入策略。
- **2029**：维持跨平台可移植协作；只有外部公开证据超出强软件基线才评估派生状态、CPU 续执行或低功耗域的独立硬件选项。

**主视觉**：按层×年矩阵，年度间使用虚线或「能力深化」箭头，2029 条件项必须用空心/虚线边框；不能用坚定的「量产/完成」时间轴箭头。高密度信息拆成层内两级短句，讲者备注承接细节。

**证据**：详细研究终稿第 13 章、正式 2027–2029 roadmap、current.md。

**备注主线**：横向逐年说明先后依赖、纵向说明 owner，明确没有获批预算、固定人力或厂商产品里程碑。

**拒收**：隐含 2029 Agent 专用 CPU 必定流片；不同层年表错位；箭头从 2027 直接表述「必然导致硬件发布」。

## S16｜16/17 — 技术决策的可信度取决于证据适用边界，而非论文数量

**页面任务**：给领导可信的研究边界，防止把图表中的「最高值」当普遍规律。

**投影必含**：四类标签「原始论文/官方文件直接事实」「跨来源推断」「待证实假设」「目前不成立的主张」；给出至少三个成对例子：
- 特定手机 CPU/NPU crossover 事实 ≠ 所有手机 CPU 更快；
- 特定 CPU SME2 加速事实 ≠ 需要新 Agent ISA；
- 软件进度调度有效事实 ≠ 私有硬件语义信息已有独立收益。
再列出测试限定：设备/模型/基线/单位/最高 vs 平均/来源谱系。

**主视觉**：从事实到结论的证据链 + 分叉「不能推出」的错误箭头（清楚打叉，不要文字含糊）；可保留来源核验清单作为小表格。

**证据**：详尽终稿第 14、15 章；原始证据卡。审计时 22 个优先 Markdown 内部链接的覆盖不等于外部全部 URL 现场访问或全部专利穷尽检索。

**备注主线**：解释来源强度、独立性、访问边界与本研究未做实验，强调不把无证据说成永久不可能。

**拒收**：使用「完全证实」「首个」「唯一」等未经来源支持的绝对性词汇；以论文数量推断因果可信度。

## S17｜17/17 — 当前优先推进工程协同，并仅在关键新证据出现时重审专用硬件

**页面任务**：给管理层三项明确可讨论的技术决策，不要求立即批准虚构项目或新试验。

**投影必含**：① 以三类现有 ISA/Runtime/Agent 工程能力为建设重点；② 三项窄研究储备保留为跟踪对象，不将其包装为现成的 CPU 设计；③ 只有外部新证据隔离了真实手机、强软件对照、物理残差和系统效果，才评估新专用硬件。结尾一句：CPU 重要，但是否值得新增 Agent 专用硅片仍需更强证据。

**主视觉**：三项决策建议与右侧「重开条件」；使用可执行、可检验的行动语言。来源标注及产品承诺限制保留在画面或备注。

**证据**：current.md、DEC-PORTFOLIO-002、DEC-A-008、正式结题验收。

**备注主线**：先讲三项决策各会改变什么协作方式，再说明公开证据范围内已结题以及何种新公开资料才需更新研究；不宣布新实验或量产计划。

**拒收**：页尾变成「后续再全面调研」的空话；把长期保留研究写成已签署研发预算；总结与 S03 方向不一致。
