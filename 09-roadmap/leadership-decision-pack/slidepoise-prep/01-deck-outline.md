## 1. 汇报的中心问题与一句话答案

**核心问题：** 2027—2029 年，Agentic AI 改变手机哪些执行行为，CPU/LLVM/SoC 应优先改变什么；在现有 NPU、Runtime/OS 与共享内存的最强公开基线下，哪些新硬件想法仍缺乏独立收益证据？

**主线答案：** Agentic AI 首先强化动态多阶段调度、可信动作、状态生命周期与低功耗准入；手机 CPU 保持可编程控制与选择性计算角色。应优先建设 **现有 CPU ISA 与 LLVM 快速路径、可信 Agent 工具执行、Runtime/OS 异构 QoE** 三类工程/平台能力，保留三类条件研究储备；**当前没有足够公开证据支持新增独立 Agent 专用 CPU 硬件主押注**。

**必须让领导在最后能够回答：**
- 变化为何真实、与传统单次模型执行有何不同？
- 哪些数据来自具体手机、哪些只是平台声明或跨来源推断？
- CPU 编译团队、Agent 平台团队、Runtime/OS 团队分别该做什么？
- 哪些研究仍值得观察、何种外部新证据才足以改变判断？

## 2. 叙事策略

- **先结论、后证据、再路线**：第 3 页先给带证据边界的核心判断；第 4–11 页建立工作负载与软硬件机制；第 12–14 页收敛分工及条件研究；第 15–17 页给路线、证据边界和最终决策。
- **页标题是一句可以独立理解的陈述句**，不是问句、主题名、研究编号或「金字塔结论」等方法论术语。
- **投影页面尽量不暴露研究过程编号**：例如 CG-06、A、B-residual、R2、F/P/V 可保留在内容合同与讲者备注；对领导展示优先使用「CPU 编译与执行快速路径」「跨引擎状态有效性」等自然语言。需要追溯时用备注标注 ID。
- **可视化优先表达因果、依赖、比较、分工或决策门槛**，不是把段落平均分进卡片。每页结论必须受证据和边界约束。
- **所有页共享 16:9 PowerPoint 框架**；但 SlidePoise 图像生成对象是扣除页眉/页脚后的实质内容区域，绝不直接把整张 16:9 生图当成可编辑成品。
- **讲者备注独立完成并验收**：先解释投影上的结构、连接关系、术语，再逐项说明来源、原始证据、支撑与不能支撑的内容。必须另行确认本地 SlidePoise 对 PPT Speaker Notes 的写入能力。

## 5. 论证关键转场

- **S03→S04：** 结论为何不直接是「做新 CPU」？因为先要理解持续 Agent 工作流改变了什么。
- **S05→S06：** DAG 表明需要分配计算阶段；分配之前必须理解真实 CPU/NPU 成本。
- **S06→S07：** 一代手机的 CPU 机会并非固定不变，优化 NPU 后端可能改变交叉点。
- **S07→S08：** NPU 持续增强，并不排除 CPU 利用现有 ISA 在形状敏感和控制密集路径继续优化。
- **S08→S09：** 单个执行资源优化之后，端到端效果仍受 DAG、共享内存与前台交互限制。
- **S11→S12：** 软件已能理解部分任务进度，下一步应该划分跨层接口而非直接增添硬件语义状态。
- **S13→S14：** 已有工程方向可推进，但硬件相关储备需要更严格的证据升级门槛。
- **S15→S17：** 路线图与证据边界最终必须落实为当下可讨论的方向与重新研究条件。
