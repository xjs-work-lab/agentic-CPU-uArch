### 2. 名词辨析与展示文案

[HeRo 原论文 §3.2 / §4.2](https://arxiv.org/html/2603.01661v2) 将 shape-aware partitioning 与下列 workload shape 配置关联：

- **batchable stage**（例如 document indexing 或 reranking）：对同一模型与 xPU（论文 PU = processing unit）离线 profile 多种 **batch size**；针对当前剩余工作量 $L$，用 **Eq.3** 选择预计总阶段时间较少的批大小 $n$。
- **streaming stage**（例如 query rewriting / decoding）：以 **token group** 为调度或阶段分割粒度，在满足依赖时及时触发后续工作，并摊销任务派发开销。
- 更广义的 workload shape 还可包含 sequence length 等推理输入配置。论文讨论的“shape”不是实体图形几何形状，也不是 CPU/GPU/NPU 的物理外形。
- **注意**：Eq.3 明确适用于可批量处理阶段的 batch size 优化；不要直接把它标成 token-group 通用最优公式。

替换具体文字：
- 页面主标题：**HeRo 通过关键任务优先、分批策略与带宽控制，降低端侧 Agentic RAG 时延**。
- 五阶段模块标题：**HeRo 根据任务关键性确定调度优先级，再综合执行时延与带宽争用选择最优执行配置**。
- 第三卡片提示：**xPU × batch size / token group**。
- 第三卡片判断：“**批量：选 batch size；流式：按 token group**”——实际分成两行，不将两种阶段口径挤成一串。
- Eq.3 模块标题：**比较 batch size 后分批**，注释写“对可批量处理阶段比较 batch size n 的预计总时间；流式阶段按 token group 切分”。

保留必要的英文技术概念，不逐字硬译为“形状感知”。对投影读者重点展示**实际调什么参数、为什么影响完成时间**，论文完整术语留在本 Markdown、原始链接和备注层中。
