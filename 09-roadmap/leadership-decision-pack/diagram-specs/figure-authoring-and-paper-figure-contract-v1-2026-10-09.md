# 图表选型、论文原图使用与证据追溯合同 v1

日期：2026-10-09。用户要求根据内容选**Python 真实数据绘图**，也允许在正确理解和解释的前提下**适当裁剪引用论文原图**。本规范在 [多语言技术图规范](diagram-authoring-policy-v1-2026-10-08.md) 之上补充**证据图**的生产路径；不强迫所有内容转成 PPT 手画，也不允许为了排版自由篡改论文数字。

## 1. 三大实际制图路由

### A. Python 程序化精确绘图

**优先使用**：论文提供原始数表、坐标、误差范围，需突出可比较数值的 bar/line/scatter/ablation、延时组成或同组性能对照。

原则：
1. 记录原始论文、图/表号、设备、任务、模型、软件版本、基线、单位、值的方向与统计口径；数据最好存成小型 CSV/JSON 与单独绘图脚本。
2. 用 Python（matplotlib 等）据实作图，禁止让图片生成模型绘制定量柱图或虚构误差条、置信区间。
3. 同一坐标系只能放可比的数值。同一页出现多篇/多指标数据时使用分开的 panel，并直接注明独立测量的基线。
4. 导出高质量 **SVG/PDF/PNG** 供 PPT 放置；如果最终需要在 PowerPoint 中直接改数据，应优先用 PPT **原生 chart** 重建，并同时保留 Python 绘图脚本/数据；SVG 不是可编辑数据系列的同义词。
5. 标签、论文短引用、标题和结论尽量用可编辑 PPT 文本层以统一字体与阅读字号。

### B. 论文原始 Figure 有选择地引用

**优先使用**：论文原生方法架构复杂，包含不易忠实重绘的数据路径、真实 trace、特殊硬件结构或细致实验热图；原图本身清楚，直接使用更易保持技术忠实。

引用前按序完成：
1. 回读论文正文、Figure 标题与图注，**每个重要节点、箭头、颜色/图例、坐标轴、单位和条件都能解释**，否则不得将原图放入正文。
2. 判断引用哪一整张或哪个**自洽子图**最直接支撑本页结论；裁剪可去除空白/无关子图，但不能隐藏会改变结论的零点、单位、置信区间、对照基线或限定说明。
3. 在制作登记中记录论文标题、作者/会议/年份、原始 URL、Figure 编号、选中子图字母、裁剪范围以及**为何裁剪不改变原意**。
4. 检查论文许可证和图形第三方权利是否允许该用途；不因为公开 PDF 可下载就自动视作可任意再分发。
5. 如果裁剪导致图中文字太小，应拆分成单独 Figure panel，或改为**重绘一张简化原理图，显著标注“依据论文方法简化重绘”**。
6. 在幻灯片上用 PPT 原生文本说明“此图说明什么、读图顺序、与结论关系、原论文设备/实验边界”，论文引用含可点击 URL。
7. 论文图片作为**独立可移动、可缩放图像对象**嵌入，不把整张 PPT flatten 成单张图片；作者原图不承诺全部节点可编辑。

### C. 本文机制摘要与管理概念

**优先使用**：Agent 任务流程、CPU/GPU/NPU 分工、LLVM/Runtime/OS 责任、未来投资门槛和路线，原论文可能没有恰当图或不同来源需要综合。

采用 Mermaid / PlantUML / Graphviz DOT / Direct SVG / PowerPoint 原生 shapes/connectors 的适合组合，先检查节点-边-语义，再作图。说明此图是“研究综合/解释性示意”，不能把合成后的抽象图伪装成论文原图或量产 SoC 的物理连接。

## 3. 每张证据图的审阅卡片（避免只粘一张图）

图名或用途：
- **支撑的论点**：本页标题的哪一部分？
- **来源**：作者、题名、会议/年、URL、Figure/Table 号；
- **我对图的解释**：主要轴/节点/箭头是什么，读图顺序是什么，哪部分能真正推出本页结论；
- **实验边界**：设备、模型、负载、baseline、精度、单位、统计量；
- **操作**：Python 重绘 / 原图完整 / 原图裁剪 / 按机制简化重绘；
- **裁剪依据**：保留的坐标轴、颜色图例、统计边界；许可/版权情况；
- **可编辑性**：原生数据 Chart / Python SVG / 可编辑 PPT 标签 / 原始 raster Figure；
- **QA**：论文内容审阅、数字对照、图内字体可读性、来源链接与最终 PPTX/PNG 一致。

## 4. 两个不能跨越的边界

1. **漂亮的图片不代表可靠证据**：无坐标、无比较对象、无基线、无来源的性能图不得使用。论文原图也必须理解并解释，不能把Figure直接当正文主结论。
2. **图在 PPT 中可移动，不等于图内所有元素可编辑**：定量图推荐保留 Python 源码/数据或 PPT 原生 chart；原论文截图本身是不可编辑 image，但其外围标注、说明、标题、链接要原生可编辑。


## 5. 每页 PowerPoint 备注中的逐来源解释（用户认可，强制继承）

2026-10-09：用户审阅正文第 12 页后明确反馈：“**可以，很不错，特别是备注对每个来源的解释说明，这个很到位，这个动作要继承好。**”这项要求从第 13–15 页开始强制执行，并在最终 17 页合并时回顾第 1–12 页已有备注，不允许只把它保存在 GitHub Markdown 而漏写到 PPTX 的 **Speaker Notes / 演讲者备注**。

### 逐来源备注卡的固定结构（每份文献或官方资料各一条）

1. **来源身份和原始地址**：题名、作者/机构、年份、论文或官方技术文档类型、直接原文 URL；具体 Figure、Table 或章节优先标明。论文与厂商文档必须区分。
2. **该来源真正证明什么**：概括可核实的技术机制或数据。量化来源标明设备、模型、软件后端、指标、单位、对照基线、统计口径；官方文档说明已提供的 API/能力与适用范围。
3. **不能据此证明什么**：特别说明不能直接推导的新硬件收益、跨设备普遍性、完整 Agent 成功率、厂商部署覆盖、未知实验条件；专利与产品实测不得混为一谈。
4. **在本页支撑哪句判断/哪幅图**：明确关联正文的标题/某张图/某个结论；若从多来源合成了进一步的工程或研究推断，须标成“**本研究的综合推断，不是来源直接结论**”。
5. **讲解提示（可选）**：用 1–2 句话说明领导可能误解的概念、示意图不代表什么，以及下一步缺哪些验证数据。

**建议每页备注格式**：

```text
本页主结论：……
来源 1｜[论文 / 官方文档] 标题 — 作者/机构、年份，原始 URL，具体 Fig/Table/§
  已证明：……
  未证明 / 适用限制：……
  本页对应：图 X / 标题中的某句 / 机制 Y。
来源 2｜……
研究综合推断：……（明确不是来源直接结论）
待验证问题：……
```

### 可视正文、备注与证据仓如何协作

- **可视页面**保留简洁结论、必要指标/基线、短来源标识和可点击引用；不把整页资料解读搬上投影屏。
- **PowerPoint 演讲者备注**保留可供汇报人解释和回答质疑的完整逐来源说明；这是可交付 PPTX 的组成部分。
- **GitHub 页面记录**保留相同证据范围与原始链路，保证重新生成或修改 PPT 时不丢失技术含义。
- 一页综合多个来源时，**不能把三个链接合写成一个大段、却不说明每份资料的独立贡献**。
- 若来源未能核实原文，必须在备注标明“尚待验证”，并在可视页面避免把相应主张写成既定事实。
- 最终 QA 必须检查：每张证据页 PPTX 含有效备注关系和非空 notes XML；备注中的 URL、来源数量、已证明/未证明/本页对应逐项齐全；与可见正文的主张一致。备注存在不代表来源已经核验，仍需人工比对原文。


## 6. Round16C：演讲者备注必须先解释页面、再解释来源（2026-10-09）

用户新要求**优先于上文第5节旧格式示例**：每页 PowerPoint 备注中的**第一部分必须是 PPT 实际页面内容的充分详细技术讲解**，沿真实图表/箭头/数字顺序解释完整逻辑、因果、条件、测量口径、局限及团队意义；**第二部分才逐一解读来源**，具体写明出处、作者/机构、发表载体、主要技术观点、论据/实验、支撑本页哪句结论、不能支撑什么，以及本研究综合推断。

因此，第5节旧示范的“本页主结论→来源1→来源2”**不得当成完整备注**；必须改成“**一、页面内容详细讲解→二、来源逐条解读**”。封面与目录先解释报告目标、章节与当前17页计数，不强凑单篇论文。新模板和17页逐页审核任务详见 [Round16C 讲者备注升级合同](round16c-speaker-notes-explanation-first-and-source-evidence-contract-2026-10-09.md)。

仅修改备注时，**全部可见PPT文字、图表、箭头、页码、超链接禁止改动**。备注内容则是此轮明确要求的修改范围，不应再用“备注零变化”作为指标。
