## V6 文字与页面布局

**主标题**：HeRo 优先推进关键任务，并减少处理器争抢，让手机 Agent 更快完成任务

**开头语**：Agent 各步骤有先后依赖；CPU、GPU、NPU 又共用内存带宽。调度器需要同时考虑“谁先做”和“怎么做”。

**模块标题**：五步在线调度：先确定任务优先级，再选择兼顾执行时间与资源占用的方案。

**主流程**（五张并排卡片、四条横向箭头）：
1. 找出当前能做的任务：前序依赖满足的任务进入待执行列表。
2. 优先处理关键任务：判断哪些任务最可能拖慢整项任务完成；结合观察到的下游和可能新出现的任务。
3. 比较不同执行方案：同一任务可考虑 CPU/GPU/NPU；对批量任务比较每批处理的数据量（batch size）。
4. 避免资源相互拖慢：筛掉超出共享内存带宽预算的配置，估计对正在执行的关键任务的拖慢。
5. 执行并更新任务状态：选择综合代价较低的配置派发；完成后更新依赖与 ready list。

每张卡片增加“**交给下一步**”说明；卡片内强调原因而非内部研究 ID。不同任务可以跨 CPU/GPU/NPU 并发，同一子任务只分配到某一个合适处理器。

**关键公式**：仅在正文展示论文 Eq.4（观测关键性+未来关键性）和 Eq.1（带宽争用引入运行时减速），分别关联第 2 和第 4 步；batch-size 的 Eq.3 及符号、无候选分支、本文对方法的简化边界留在 Speaker Notes 和 Markdown 中。**这两条式子保留了论文机制，不要求不熟悉本领域的管理人员自行推导。**

**数据**：文档问答（论文 C1，Qwen3 / Workflow 2 / FinqaBench）：5.79→3.82 s；多步研究（论文 C2，BGE / Workflow 3 / 2WikiQA）：17.23→5.38 s。论文 Table 3 中的基线是 Ayo-like **固定分配处理器**，同机 Snapdragon 8 Gen 4；两组模型/工作流不同，不拼成一条曲线或共用单一数字收益。不将这些数字说成本团队实测或所有手机普适结果。

**底部启示**：现有软件/Runtime/OS 的异构资源调度有工程价值；不能从这些结果直接推导出新 Agent 语义 ISA 的独立硬件投资价值。
