## 二、五步“输入—计算/判断—输出”合同

| 步骤 | 输入 | 决策依据及操作 | 输出，传给后继 |
|---|---|---|---|
| 1 更新可执行任务 | 上一轮完成的子阶段；agent 决定后新显现的阶段/依赖 | 维护部分可观察 DAG `G_obs(t)`；仅前驱完成的节点列入 ready set `R(t)`；正在执行节点另存 `A(t)` | 更新的 `G_obs(t)`、`R(t)`，以及 active state 供第 2、4 步 |
| 2 选关键任务 | 当前 ready/active 节点、已观察到的下游路径、历史 workflow 激活先验 | Eq.4：观测路径关键性与未来可能被激活的工作共同决定 CS；从 ready 中取最高 CS 的候选 `v_cand`，从 ready∪active 中辨认当前关键节点 `v*` | 第 3 步需要 `v_cand`；第 4 步的 contention penalty 还需要 `v*` |
| 3 枚举执行方案 | `v_cand` 的模型与剩余 workload、能运行它的 PU 集合、离线 profile 数据 | 为可执行 PU `k` 枚举 shape-aware configs（例如 batch/token-group），Eq.3 说明批次大小对总代价的作用；**不假设所有 PU 对任务相同高效** | 候选 `c=(k,shape)`、配置对应的预测延时 `p_v^0(c)` 与带宽 `b_v(c)` |
| 4 控制争用并评分 | 候选的预测延时/带宽，当前活动集合 `A(t)` 与 `B(t)`、关键节点 `v*` | 首先拒绝 `B(t)+b_v(c)>B_soft` 的配置；再依据 Eq.1 的压力减速估计及 Eq.5 的关键路径干扰惩罚，比较预期完成时间；Alg.1 line13 的评分结合 `F_{v*}` 与 `α W_B` | 所有通过预算的配置及其评分；无可行候选时按 Alg.1 line15 换下一个 ready 节点，不强制派发 |
| 5 选配置并派发 | 当前候选的可行配置评分、PU 空闲状态 | 选择评分最优的一个 `PU×shape` 配置，将**当前候选节点**派给一台 PU；此后更新 active 集合和 DRAM 需求。可以在不同空闲 PU 上为不同子阶段继续调度 | 当前选择与更新后的 `A(t)` / `B(t)`；阶段完成后进入下一次迭代，更新 DAG 和 ready |

**注意**：对每个子阶段选单一 PU 与“同一时刻只运行一个 PU”完全不同。论文允许不同子阶段并发执行，但用带宽控制抑制有害干扰。V3 不画三条 CPU/GPU/NPU fanout，也不画跨越主图的大反馈线；用简洁说明带表达下一次调度循环。

## 三、论文三个核心公式及本页解释

### 关键路径优先：Eq.4

\[
CS(v)=CS_L(v)+\beta\,CS_F(v)
\]

- `CS_L(v)`：在当前**已观察部分 DAG**上，从节点出发估算的剩余最长路径关键性，视算法中任务映射/依赖预测而更新。
- `CS_F(v)`：在预先定义的 workflow 图与历史激活倾向下，预测未显现的后续活动可能带来的关键性。
- `β`：作者配置的未来项权重，不能写成固定的通用硬件门槛。
- **强调**：不是“把当前 DAG 里路径最长的任务无条件放 NPU”，而是确定哪个 ready 任务最应优先获得资源，再进入适配和带宽判断。

### 可适配的工作分区：Eq.3

\[
n^*=\arg\min_{n\in N_{m,k}}\Big\lceil\frac{L}{n}\Big\rceil\, p^0_v(c_v),\quad c_v=(n,k)
\]

- `L` 为阶段剩余负载规模；`n` 为批处理或工作单元粒度；`N_{m,k}` 为该模型/PU 组合中已分析的候选批大小集合；`p^0_v(c_v)` 是无共享带宽干扰时、经离线 profile 得出的调用时延。
- 意图是让 **工作单元数量 × 每单元时间** 尽量小；大 batch 并非总是最优，streaming 阶段可用 token-group partition。
- **注意**：Eq.3 在文中归属于 shape-aware sub-stage partition，并不表示每个 Agent 工具动作都调用该公式。

### 动态带宽成本：Eq.1

\[
p_v(c_v,B(t))\approx p^0_v(c_v)\,\phi_{v,c}(B(t))
\]

- `p^0_v` 为该子阶段配置下的无争用延时；`φ_{v,c}(B)≥1` 表示共享 DRAM 需求提高时可能产生的减速。
- Algorithm 1 还实施 `B(t)+b_v(c) ≤ B_soft` 软预算检查，并对当前关键节点的性能退化施加惩罚；目标是减少任务端到端延时，不是让所有可用 PU 无条件持续满载。
- 论文 Eq.2 的总目标 `T=max_v F_v` 用作讲述时的补充，而非在 16:9 页面堆入第四个公式。

**变量口径**：`v_cand` = 选出的待派发 ready 子阶段；`v*` = 当前（ready/active）关键节点；它们未必是同一个。页面可以省略下标样式，但技术备注与 Markdown 不能混为同一变量。
