Updated: 2026-10-07  
Authority: leadership/management view derived from the V2.2 Research SSOT.

## Executive decision

The research does **not** support filling a 2–3 Primary-Bet quota.

The evidence-converged portfolio contains:
- **1 differentiated Primary Bet:** A — Agent Semantic Progress Control;
- **1 competitive investment:** CG-06 — CPU-Resident Latency-Critical Agent AI Fast Path;
- **2 platform must-build tracks:** PT-A and C;
- **2 measured competitive options:** CG-07 and CG-01;
- **3 Strategic Reserves:** B-residual, R1, R2;
- **1 blocked hardware route:** R3;
- **0 uArch Primary Bets today.**

This is the intended conclusion, not a gap to be cosmetically filled.

## 2027 — Measure, falsify, and build software/platform foundations

### A — decisive differentiated-Bet gate
Run EXP-A-001.

Pass only if explicit DemandState/RequiredProgress provides roughly >=5% meaningful end-outcome value over B4-TX at matched foreground QoE and zero illegal cancellation.

Kill/downgrade A if the strongest history/runtime/utility/topology/legality baseline reproduces nearly all value.

A positive result is **not** a hardware result. It only earns target-phone SYSTEM_VALUE and opens an A→C software/system-control test.

### CG-06 — competitive execution priority
Run EXP-CG06-001 across CPU-VECTOR, CPU-MATRIX, NPU-BASE, NPU-OPT and HETERO-OPT.

A CPU fast-path region counts only if it survives optimized NPU/HETERO execution after dispatch, fallback, layout, precision, state reuse, energy, thermal and full critical-path accounting.

Use existing ISA/compiler/runtime first. No new matrix ISA proposal from this gate.

### PT-A — platform contract
Run EXP-PTA-001 and EXP-PTA-002.

Build toward:
capability/authority-aware routing → target/context binding → bounded effect → OutcomeReceipt → verification → bounded recovery.

If a cheap fresh-context check plus strong software verification closes action misbinding, keep the solution in OS/runtime and do not open hardware.

### C — system-control substrate
Run EXP-C-001 against G2 Agent-aware heterogeneous orchestration.

A separate C differentiated mechanism survives only if it provides >=~5% reusable value beyond strong generic and Agent-aware software controls across more than one representative Agent regime.

If the only incremental signal is A's DemandState, classify it as A→C transfer rather than a second Primary Bet.

### CG-07 / CG-01 — measured options
CG-07: collect real context rate, acceptance rate, gate cost, wake/handoff, idle/residency, battery, thermal and foreground QoE; promote only if dedicated front-end economics beat the strongest software-sparsified shared/CPU baseline.

CG-01: measure continuation locality under default, strong affinity/pooling/warm-core and generic shared/coherent-cache baselines before considering adaptation.

### Reserves
Run phone-input collection for EXP-BR-001, EXP-R1-001 and EXP-R2-001.

A reserve needs >=~5% incremental value over its strongest baseline; otherwise close it rather than carrying it indefinitely.

## 2028 — Productize only the survivors

### Expected platform path
Regardless of differentiated-Bet outcome, product work should converge around:
- heterogeneous verified actuation (PT-A);
- heterogeneous system-control substrate (C);
- CPU/NPU/HETERO placement and fallback optimization (CG-06);
- state/version/reuse lifecycle capabilities needed by T5/T6/T8.

### If A passes
Standardize a narrow semantic-progress contract at Agent/runtime/OS level first.
Measure metadata/IPC/control overhead and whether C can use it to improve useful progress, energy or QoE.

Do not jump directly to CPU hardware.

### If CG-06 passes
Productize selective CPU-resident or mixed CPU/NPU fast paths using existing ISA/compiler/runtime mechanisms.
Keep operator/stage/precision/layout boundaries adaptive because optimized NPU coverage can move the crossover.

### If CG-07 or CG-01 passes
Advance to architecture co-design only after measured SYSTEM_VALUE.
A vendor/product gap is not enough by itself.

### If reserves fail
Retire B-residual/R1/R2 individually.
Do not preserve them merely because they are plausible.

## 2029 — Hardware only after software insufficiency

A CPU/uArch candidate may exist only if one surviving path completes:

STRUCTURAL_SIGNAL → SYSTEM_VALUE → SOFTWARE_INSUFFICIENCY → hardware-specific cause → UARCH_CANDIDATE.

Possible hardware work is therefore **conditional**, not preselected.

Examples of valid activation:
- A proves non-reconstructible semantic value, OS/runtime consumes it, then a repeatable hardware-timescale visibility/control bottleneck remains;
- R2 proves a real phone CPU-local microstate penalty after strong affinity and generic shared-cache capture;
- CG-07 proves dedicated-domain economics on real phone traces after lightweight gating;
- CG-01 proves a continuation-locality gap not solved by generic shared/coherent cache.

Absent such evidence, the 2029 roadmap remains software/runtime/platform-heavy and that is a successful evidence-based outcome.

## Strategic Reserves — final definition

### B-residual
Question:
does semantic/workflow revision expose S2/S3 artifact validity/preservation information unavailable to strong workflow/history prediction + version/hash/provenance/dependency/runtime state?

Gate:
EXP-BR-001; >=~5% matched-outcome gain; stale reuse = 0; survives memory pressure.

### R1
Question:
does explicit ReleasePermission/LatestUsefulResume expose post-ready timing value unavailable to strong generic release/slack/wake/migrate scheduling?

Gate:
EXP-R1-001; >=~5% value with bounded/zero hard-deadline violations.

### R2
Question:
does Agent continuation leave a phone CPU-local cache/TLB/branch microstate residual after strong software locality and generic shared/coherent cache?

Gate:
EXP-R2-001; >=~5% causal incremental performance/energy value.

## Kill / Do-Not-Invest

Do not fund as standalone differentiated programs:
- T6 local programmable Agent execution;
- T7 local multi-Agent concurrency;
- T8 cross-device continuation;
- H-CAL contiguous Agent learning;
- H-PAM standalone route;
- broad Persistent Agent State Fabric;
- broad Ready≠Release mechanism;
- generic cache/TLB/predictor restore or cache-aware migration;
- generic semantic scheduling hints;
- new CPU ISA/uArch merely because Agent workloads exist.

These topics may still be product requirements inside PT-A, C, T5/B-residual, CG-06, CG-07 or CG-01.

## Product-evolution interpretation

Product relevance remains broader than differentiated research:
- T1–T6 and T8 are product-relevant at different maturity levels;
- T7 remains FRONTIER_SIGNAL / WATCH;
- prior art does not kill product value;
- product maturity never bypasses the hardware gate.

## Leadership takeaway

The strongest 2027–2029 strategy is **software/platform-first with one tightly falsifiable differentiated semantic Bet and a disciplined set of competitive/reserve measurements**.

The roadmap should be judged successful if it quickly kills weak residuals and prevents premature uArch investment, not by how many hardware ideas survive.
