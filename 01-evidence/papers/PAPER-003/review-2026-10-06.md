## Q1 — Problem + target mapping

### Paper problem
Background on-device LLM inference and latency-sensitive foreground applications share mobile SoC memory bandwidth.

The evaluated system shows a strongly asymmetric failure mode:
- foreground UI QoE degrades sharply;
- NPU LLM throughput barely degrades;
- the NPU inherits high-priority memory treatment designed for genuinely latency-critical media pipelines.

On the OnePlus 13 characterization:
- aggregate foreground jank across 25 apps increases by **153%**;
- LLM prefill throughput falls only **1.01%**;
- decode throughput falls only **1.64%**.

Root-cause profiling attributes the dominant effect to **shared DRAM bandwidth / memory-access-latency contention**, not simple CPU/GPU saturation or cache contention.

### Project mapping
This is direct evidence for one of our most important user scenarios:

> **Foreground-Protected Persistent Agent / background AI**

It is closer to the target smartphone than most of our Agent-runtime literature.

But the background workload is LLM inference, not a full persistent Agent. Therefore it establishes:
- the user/system conflict;
- the shared-resource mechanism;
- a strong generic protection baseline;

not an Agent-specific semantic residual.

## Q2 — Novelty / new-regime relevance

Foreground/background interference and memory-bandwidth QoS are old problems.

The new regime is:
- high-throughput NPU inference;
- UMA smartphones;
- accelerator traffic with legacy high-priority media semantics;
- best-effort AI overlapping millisecond-scale interactive rendering.

Classification:
**Agent-amplified / on-device-AI-amplified**, not Agent-native.

SERENO's mechanism novelty is also cross-layer rather than new hardware:
- repurpose speculative decoding from an acceleration method into an interruptibility/QoS substrate;
- derive an endogenous contention signal from LLM execution itself;
- regulate NPU memory pressure without requiring new hardware controls.

## Q3 — Falsifiable hypothesis

The paper tests:

> If foreground degradation is caused by excessive NPU memory-bandwidth pressure, and LLM execution can expose sufficiently fine-grained safe yield points, then dynamically yielding bandwidth based on real-time contention should recover foreground QoE without destroying LLM progress/throughput.

Falsifiers would include:
- no causal relationship between NPU traffic and foreground jank;
- contention cannot be sensed at useful granularity;
- preemption/yield overhead destroys throughput or energy efficiency;
- yield control cannot generalize across foreground app categories or hardware generations.

The evaluated evidence supports the hypothesis within its Snapdragon scope.

## Q4 — Research lineage / competing route

### Research lineage
SERENO sits within a sustained IPADS local/mobile LLM systems line:
- **PowerInfer** — consumer-grade LLM serving;
- **PowerInfer-2** — fast LLM inference on smartphones with CPU/NPU/storage co-scheduling;
- **PowerServe** — the QNN-based mobile inference substrate used as SERENO's baseline;
- related IPADS work on local inference, storage and heterogeneous execution.

This matters because SERENO is built on a group with direct mobile-LLM systems expertise rather than being an isolated QoS study.

### Competing routes / baselines
The paper compares against:
- Native foreground-only upper bound;
- PowerServe;
- llama.cpp CPU/GPU/NPU backends;
- MNN;
- static NPU frequency limiting;
- fixed-duty-cycle Chunk-Sleep;
- throughput-oriented speculative decoding.

Relevant prior mechanisms outside the paper's exact stack include:
- hardware memory-bandwidth partitioning / QoS (e.g. RDT/MPAM-class mechanisms);
- CPU/GPU bandwidth throttling;
- generic foreground/background priority.

### Project lesson
Any C/R3 proposal must not claim generic foreground protection or memory-bandwidth QoS as new.

## Q5 — Key mechanism / control point

SERENO implements a **Sense → Decide → Act** loop.

### Sense — endogenous contention proxy
Instead of requiring unavailable high-rate NPU bandwidth PMUs, it uses execution latency of memory-intensive draft subgraphs as a contention proxy.

Reported correlation:
- **Pearson R ≈ 0.86** against the physical contention measure in the useful range.

This gives sub-millisecond feedback using workload-internal timing.

### Act — Elastic Speculative Decoding
Speculative decoding creates draft/verify structure that can be made interruptible.

Key actuators:
1. **Draft preemption** — abort tentative draft work when contention rises;
2. **Selective batching** — choose among precompiled verification graphs with different batch sizes/bandwidth profiles;
3. **Micro-sleeps** — introduce short gaps between verification subgraphs.

N-gram Filling is then used to recover throughput lost to aggressive yielding.

### Decide — PI controller
A PI controller maps contention score to actuator intensity, with:
- Balanced policy;
- UI-First policy;
- throughput guardrail / fail-safe behavior.

### Strategic control point
The important project-level seam is:

> **foreground QoE budget + background AI progress → dynamic shared-bandwidth usage**

But SERENO shows this seam can be implemented in software above unchanged commodity hardware.

## Q8 — Evidence vs hypothesis

### [FACT — direct smartphone evidence]
On evaluated OnePlus/Snapdragon phones, concurrent NPU LLM inference can substantially increase foreground jank while the background inference itself loses little throughput.

### [FACT — mechanism]
The paper shows a strong association between draft-subgraph latency and contention and demonstrates a software control loop that uses this signal to yield NPU bandwidth.

### [FACT — reported end-to-end results]
Against PowerServe:
- foreground jank reduction up to **92.6%**;
- **58.5% average** reduction;
- LLM throughput improvement up to **67.9%**;
- **26.4% average** improvement.

Against vanilla speculative decoding:
- up to **72.1%** jank reduction;
- only **6.2%** throughput degradation in the cited comparison.

Energy:
- SERENO: **3.52 tokens/J**;
- throughput-oriented speculative baseline: **3.78 tokens/J**;
- CPU route in the reported comparison: **1.81 tokens/J**.

Overhead:
- ~**4.7% of one CPU core**;
- **+0.86 GB memory (+19%)**, dominated by the 1B draft model;
- SERENO-specific static graphs add **<70 MB**.

### [OBSERVATION]
The highest-throughput accelerator policy is not necessarily the highest-user-value system policy.

### [INFERENCE — project]
Persistent mobile AI must be evaluated against **foreground QoE as a first-class budget**, not just AI latency/energy.

### Not established
- full Agent end-to-end value;
- DemandState value;
- Huawei device transfer;
- universal NPU priority behavior across all SoCs;
- need for new hardware QoS mechanisms;
- software insufficiency.

## Q9 — Real contribution to the project decision

### Foreground-Protected Persistent Agent anchor
**Strongly strengthened.**

Before this paper, the anchor could be argued from product intuition and mixed-criticality principles.

SERENO gives direct smartphone evidence that:
> background mobile AI can consume shared resources in a way that preserves its own throughput while visibly harming the foreground user.

That makes foreground QoE a mandatory evaluation axis for our roadmap.

### A — Agent Semantic Progress Control
**No promotion.**

Existing `CLM-MOBILE-001` correctly uses SERENO as a strong generic baseline.

A must show that semantic DemandState/RequiredProgress preserves more useful Agent progress than a SERENO-like generic foreground-protection mechanism at a matched near-native QoE envelope.

### C — Efficient System-Control Substrate
**Problem relevance strengthened; strongest baseline strengthened; lane/score unchanged.**

SERENO is direct target-class phone evidence that the system-control problem is real.

But it also captures a large amount of value without new hardware and without Agent-native semantics.

Therefore C's G1 baseline should explicitly include:
- foreground-QoE-aware bandwidth sensing;
- fine-grained yielding/preemption;
- elastic batching;
- throughput guardrails.

C gets differentiated credit only for **Agent-specific residual beyond this**.

### CG-06
**No lane/score change.**

One secondary lesson matters for future experiments:
CPU/NPU placement should account for the externality imposed on foreground shared-memory QoE, not only the latency/energy of the AI stage itself.

This is an experiment-design implication, not new CG-06 proof.

### R3 / uArch
**Remain BLOCKED.**

The paper explicitly identifies missing/awkward hardware capabilities:
- fine-grained NPU bandwidth visibility;
- high-frequency control;
- portable per-client bandwidth quota.

But its central result is that a software-only workaround already produces large value.

Therefore the paper shows a potential hardware seam but **does not establish SOFTWARE_INSUFFICIENCY**.

### Second-Bet search
The broad candidate:
> "Foreground-Protected Persistent Agent Control Plane"

is **not yet a differentiated second Bet**.

Generic mobile LLM QoS control already occupies a large part of that space.

A surviving second-Bet hypothesis must prove:
- an Agent-specific state/control variable;
- additional value beyond SERENO-like generic contention control;
- transfer across representative Agent workloads;
- a reusable control point inside the team's scope.

## Q10 — Next action

1. **KEEP PAPER-003 as P0**.
2. Treat SERENO-like foreground-QoS control as part of the mandatory **G1/B4 strong baseline** for A and C.
3. Add `CLM-MOBILE-001` explicitly to C's supporting/baseline chain.
4. Require future phone experiments to report:
   - foreground jank / frame deadline misses;
   - background useful progress;
   - memory-bandwidth pressure;
   - energy/thermal;
   - matched QoE envelope.
5. Do not propose NPU bandwidth hardware or new uArch from this paper alone.
6. If later phone experiments show residual because software cannot observe/control fast enough, then reopen the hardware gate with direct causal evidence.
