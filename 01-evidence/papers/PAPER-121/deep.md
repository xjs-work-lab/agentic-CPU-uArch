## Q1 — Problem and target mapping
Multi-agent workflows need to choose which specialized/size LLM executes each worker role after the coordinator plans it, accounting for evolving task progress and time/energy budgets. AO-5 mapping: how much of 'semantic progress' is derived from observable runtime workflow records rather than irreducible Agent-private requirements?

## Q2 — Novelty/new-regime relevance
Agent-workflow-progress-guided *software LLM model routing*, not CPU task scheduling. Each agent step selects a model; a coordinator handles subtask planning and maintains a ledger of objectives, prior outputs, intermediate reasoning and state. The user goal and subtask completion criteria are registered within that runtime.

## Q3 — Falsifiable hypothesis
Multi-view progress scoring and online model-specific predicted gain improve task success under a specified cost budget versus static query-level route, reactive escalation or historic guessing. Falsifiers include weak cross-domain progress proxies, unaccounted coordinator cost, model family shifts or failure to keep budget on different workload sequences.

## Q4 — Research lineage and strong baselines
Adjacent MasRouter (one-shot query-level multi-agent routing), CASCADIA (stall-triggered escalation), Educated Guessing (historically best model). Coordinator architecture uses AG2/AutoGen lineage and the progress/cost control uses virtual queues in stochastic online scheduling. The paper measures four agent-workflow benchmark types but does not directly compare against LAS PAPER-119 or B4-TX in one system.

## Q5 — Detailed mechanism / information provenance
1. Coordinator's **structured workflow ledger** has goal, roles, past actions/outputs, subtask completion and task state.
2. Progress scorer g(s) combines outcome regime {invalid, recoverable, partial success, complete}, subtask-fulfillment fraction, recent progress trend and state-quality/semantic-change score; **domain-specific observable milestones and regimes are manually configured**.
3. Dual-path predictor: structured tabular features (progress/history/role/candidate model) and **semantic embedding of a compact text summary generated by the coordinator from the existing state ledger**. Adaptive meta-learner fuses paths; online exploration/update learns realized next-step progress.
4. Router maximizes model-specific estimated progress gain weighted by remaining progress gap, with penalties for per-task latency/energy and virtual queue of average budget violations.
The 'semantic' path is a semantic interpretation of software-visible coordinator state, **not** evidence that an OS/CPU must consume an inaccessible Agent oracle.

## Q6 — Experiment design, normalized results and ablation
Benchmarks: HumanEval Plus all 164 items; MBPP random 200; MATH-500 random 200; ASQA 100. Different model zoos for programming/math/QA; single GPU workstation (NVIDIA RTX PRO 6000 Blackwell, Ollama 0.24.0, AG2 0.11.3); Qwen3-Coder-Next 80B-A3B coordinator. Budgets are **separate per benchmark** (4800J, 4500J, 7000J, 19000J): not comparable as a single ratio.

Main Table 1:
- HumanEval+: ProgRouter **93.0% pass, 4796 J, 13.7 s**; MasRouter 90.9%/4483 J/13.2s, CASCADIA 84.8%/4658 J/16.6s. Under the 4800 J cap, ProgRouter has higher pass but not best joules/time.
- MBPP: **79.4% pass, 3376 J, 10.3s**; CASCADIA 78.5%/3857J/13.3s, MasRouter 67.8%/3700J/11.5s.
- MATH-500: **84.3% pass, 6112J, 19.0s**; CASCADIA achieves **87.8% pass** at 6875J/24.6s. The paper's blanket 'best quality–cost' is a Pareto interpretation, not 'always highest accuracy'.
- ASQA: **92.1% citation precision** within 19000J budget; this is a proxy for source attribution, not confirmed holistic user outcome quality.

Appendix E Table 3 progress prediction MAE: structured only 0.0967, semantic only 0.0788, mean fusion 0.0843, adaptive meta-fusion **0.0720**.
Appendix E Table 4 HumanEval+ (same benchmark/cap): full **93.0%, 4796J**; no predictor **89.0%, 4785J**; structured-only **90.9%, 4400J**; semantic-only **87.2%, 4784J**; no multi-view scorer **90.2%, 4486J**; no budget penalty **87.8%, 4252J**; no virtual queue **92.7%, 4406J**; naïve progress-per-cost **17.7%, 7797J**. Caution: energy differs between ablations; the semantic-vs-structured difference is *not a controlled isolated hidden-information gain at matched energy*.

## Q7 — Measurement boundary and reproducibility
Appendix D.2: NVIDIA NVML GPU-board power sampled every **100ms**, integrating active GPU energy; calibrated model-call estimator includes cold load, prefill, decode and coordinator/worker GPU execution. **CPU orchestration, host RAM, storage and networking energy are excluded** as negligible by paper assumption. These numbers are *not smartphone battery, NPU rail, screen-off or system energy*.
Online evaluation uses fixed-seed shuffled sequential task stream with cold initial predictor and epsilon-greedy exploration. Full independent code/artifact replication not established by current review. Benchmark-domain rubric/milestone adaptation remains necessary. Controlled device benchmarks with privacy/permission and foreground pressure are absent.

## Q8 — Facts versus inference
**[FACT]** The paper's progress scorer uses observable coordinator state/ledger and a generated semantic summary, with model-specific online prediction and budget-aware routing. **[FACT]** Ablations show structured+semantic fusion and budget terms affect pass and GPU energy. **[OBSERVATION]** meaningful 'semantic' progress can be extracted *inside software from existing workflow state*. **[INFERENCE]** AO-5 B4-TX must include coordinator-ledger progress, semantic-summary embedding, task-progress trend and model-specific gain predictors. **[NOT ESTABLISHED]** equivalence to privileged Agent RequiredProgress, post-kernel incremental information value or phone system benefit.

## Q9 — Decision impact for AO-5/A/C and cross-opportunity model
**STRENGTHEN B4-TX / KEEP-NARROW AO-5.** Broad 'semantic progress hint' novelty becomes even less credible; but no experiment compares two histories identical under all B4-TX-visible state yet different in genuine internal required-goal closure. AO-1 can use the software planner's model-stage/role signal; AO-4 remains an event/intent gate; no evidence for new CPU-uArch control field. Do not update A Primary Bet score solely from this paper.

## Q10 — Smallest discriminating next evidence
1. Test semantic-summary/state information already inside B4-TX versus a *genuinely private* Agent RequiredProgress variable; lock a fair shared utility/outcome and latency/energy budget.
2. Identify whether phone task priority, CPU-NPU handoff, wake or state preservation is actually improved beyond software-only routing; account for predictor and coordinator CPU/memory energy.
3. Search independently reproduced progress model routing and mobile deployment; validate source/publisher final EMNLP text when available.
