# CLM-T6-004

## Proposition
Android AppFunctions substantially raises the strongest software/platform baseline for T6: function registry, typed schema, permissions, enabled state, discovery, execution and callback lifecycle can be represented as Android-visible software state, while the official APIs do not establish arbitrary Agent-generated native/JIT executable code.

## Current interpretation
This supports T6 as an emerging **product trend** while narrowing standalone differentiation to genuinely dynamic executable artifacts that create measurable phone-local costs beyond AppFunctions + T5 + PT-A + C.

## Boundary
This does not rule out future WASM/DSL/bytecode/JIT residuals; those require direct target-phone evidence.
